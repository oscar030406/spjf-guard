# 0003 Guard parameters are selected on validation traces only and must satisfy the harm constraint

The promise `G` determines `Bmax = k(G - (3 - 2/k)L)`; this step does not touch data. The remaining `B0` and `eta` have to be picked from 15 grid points, and the only basis for picking them is data. In the precheck phase they were picked on the main development traces, that is, parameters were chosen on the same traces on which results were reported.

The rule is changed as follows. The candidate set is the validation overlay traces, which contain no test term: five overlays × three load levels, 15 cells in all. A configuration is feasible if and only if its harm is at most `G/2` in **every cell**. The objective is the gap closed in the worst cell. Ties are broken in order by smaller worst harm, smaller `B0`, smaller `eta`. Once selected, the configuration is applied unchanged to the test traces, with no retuning.

Two reasons. First, the traces used to pick parameters and the traces used to report results must be separate; otherwise part of the reported gap closed comes from the selection itself. Second, the constraint is taken over "every cell" and not "on average" or "in one cell": an independent review found that when only one cell is considered, the winner at `G = 600` (`30k/4, eta 0.9`) reaches a harm of 358.9 seconds on another overlay, above the 300-second limit, whereas the per-cell constraint selects `120k/4, eta 0.75`, with worst-cell harm 293.3 seconds and worst-cell gap 0.7216 against 0.7210. The constraint costs almost nothing, but what it blocks is a configuration that would violate the limit on a different overlay.

The same rule is applied to the fixed-budget subfamily (`eta = 0`), so the statement "under the same promise, a capped relative budget beats a fixed budget" is made against **the best fixed budget the rule allows**, not only against `B0 = Bmax`. The cost is that selection has to run all 15 cells rather than 3.

2026-09-20: this rule has now been run over all 15 cells by the package itself (`scripts/select_parameters.py`, five validation overlays × three load levels, 48 grid points plus two references per cell). It selects exactly the three configurations pinned in the configuration: `(30 k/4, 0.5)` for `G = 300`, `(120 k/4, 0.75)` for `G = 600`, and `(120 k/4, 0.9)` for `G = 1200`. Compared one by one on the 45 configurations shared with `prechecks/main_v3/v31/select_worst.csv`, the largest difference in worst-cell gap is 9.6e-6 and in worst-cell harm 2e-6 seconds, and not a single feasible/infeasible verdict differs. The numbers of the example above also match: `(120 k/4, 0.75)` has worst-cell harm 293.29 seconds and worst-cell gap 0.7216.

2026-09-20 (third round): the rule itself is unchanged; the search range changed. An independent review pointed out that the fixed budget was picked from only four values and the relative budget from fifteen, so the two sides had different densities (G1 in `prechecks/main_v31_verify/out_VERDICT.txt`). Now each of the three budget shapes has a grid written in advance with comparable density (42 / 162 / 54 points). The same rule is run once within each family to give the ablation rows, and once more over the three families together; only that winner is the paper's Guard(G). See ADR 0005.
