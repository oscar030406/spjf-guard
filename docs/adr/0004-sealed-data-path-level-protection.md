# 0004 Protection of sealed data sits at the path layer and is lifted only by the protocol lock plus an explicit switch

What has to be prevented is not "the file was opened" but "the method was changed after seeing the test results". Conventions, comments and code review cannot stop a casual `read_parquet`, and on disk the sealed terms sit right next to the development terms.

The protection is written in `src/spjf_guard/data/sealed.py`. The sealed terms, the ACcoding id block and the OULAD academic year are named in this one place only. Any call that would read them must first pass `guard_semesters` / `guard_id_block` / `guard_oulad_year`, and these three functions always raise `SealedDataError` until two things hold at once: a **frozen** `protocol_lock.json` exists in the root directory (the draft `protocol_lock.draft.json` does not count), and the caller has explicitly passed `--unseal`. The same place also holds a whitelist of development terms: a term that is neither on the whitelist nor a sealed term raises an error, so that an extra term cannot slip quietly into the training set. Every permitted sealed read appends one row to `docs/sealed_access_log.md`, with exactly the six columns that ledger already has.

Both conditions are required together because they guard against different things. The protocol lock ensures the method was fixed before the read; `--unseal` ensures the read was an active decision by someone and not the side effect of a default argument. Neither is enough alone: with only the lock, a routine rerun would read the data in passing; with only the switch, the method could still be changed after seeing the results.

The refusal happens before any file is opened, so it can be tested on a machine that has no sealed data: none of the tests in `tests/test_sealed_data.py` touches any data file. The cost is one extra manual step on the day of unsealing: renaming the draft to `protocol_lock.json`. This step is deliberately not scripted. (Amended 2026-09-25: the step became `scripts/freeze_protocol.py`, which writes the lock only from a clean, committed tree whose checks all pass. ADR 0007 says why renaming the draft no longer counts as a freeze, and section 2 of `docs/sealed_run_procedure.md` gives the command.)
