# 0005 护栏是一个机制，预算形状是设计自由度；三张网格同等密度，胜者由规则选

日期 2026-09-20。

## 决定

护栏只有一个机制：被超越的工作量 `over[q]` 超过预算就强制派工。它的保证只依赖上限

```
B_max = k (G - (3 - 2/k) L)
```

预算在上限之下长什么样，是设计自由度，不是另一种机制：

```
budget(q, t) = min(B0 + gam * (q 到达时在等的任务数) + eta * k * (t - a_q), B_max)
```

`eta = gam = 0` 是常数预算，`gam = 0` 是随等待时间放宽的预算，两者都为正是随队列长度放宽的预算。三种形状写成三张**预先写定**的网格（`configs/main.yaml` 的 `scheduling.selection.grids`，各 42 / 162 / 54 个点），用同一条规则选：

- 可行：在五条验证叠加 × 三档负载的**每一格**，伤害都 ≤ G/2；
- 目标：最差格的截止窗口 p99 缺口收回；
- 同分：更小的最差格伤害，然后更小的 `B0`、`eta`、`gam`。

规则跑四遍：三个家族各跑一遍，得到三条消融行（Guard-fixed / Guard-age / Guard-queue）；三个家族合起来再跑一遍，胜者就是论文里的 **Guard(G)**。

一个常数预算自带的承诺是 `B0/k + (3 - 2/k)L`，小预算承诺的比 G 松，所以一个固定点只有在它**最差格的实际承诺 ≤ G** 时才算 G 的候选。这样三个家族在同一个 G 上比的是同一件事。

## 为什么

独立复核对 v3.1 提了一个 CRITICAL（`prechecks/main_v31_verify/out_VERDICT.txt` 的 G1）：固定预算是从**四个**值里挑的，相对预算是从**十五个**里挑的，于是固定家族在它的选点上伤害约束是松的，报出来的差距有一部分是搜索密度不同造成的，不是机制造成的。

两种修法。一种是把固定家族的网格补密，只比两种形状；另一种是承认预算形状本来就是自由度，把第三种（队列长度项）也放进来，三张网格同等密度，让规则去挑。选后者，因为它说的是实话：论文要主张的是「这个上限给了逐任务承诺」，不是「相对预算这种写法比常数写法好」。把胜者叫 Guard(G)、把三个家族的最好点作为消融行一起报，读者能看到形状换来的到底是多少。

## 代价

- 选参从 15 个点变成 258 个点，一个 cell 从约 190 秒变成约 20 分钟，15 格约 5 小时。因此逐 cell 落盘、可断点续跑，`--part/--nparts` 还能把一个 cell 拆开。
- 队列长度项使乘法形式的界不再适用：`(1-eta)W ≤ W_FCFS + B0/k + (3-2/k)L` 是对**每个任务相同**的常数部分说的，而 `B0 + gam w_q` 因任务而异。所以 `gam > 0` 时只主张加法形式 `W ≤ W_FCFS + B_max/k + (3-2/k)L`——这正是承诺 G 的定义式。代码里 `guard_upper_bound` 按这个分支走，逐任务断言照跑。
- 仿真器要多带一个参数。内核把常数部分 `B0 + gam w_q` 在写进线段树之前夹到上限，这不改变任何调度（预算本来就和上限取 min），但让整数比较留在 int64 里。

## 没有改的

上限的公式、伤害约束的比例（G/2）、目标与同分次序、验证集与测试集的划分，都和 v3.1 一样。跳过型护栏（Skip）仍是按派工计数的另一种机制，不在这三张网格里。
