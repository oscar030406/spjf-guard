# Map of generated artefacts

Every file that a script or model produces from other files has one row here: source → artefact → regeneration command → check command. Editing an artefact by hand makes its check fail. `scripts/check_generated.py` runs every check row; pre-commit calls it.

All commands assume the repository root as the working directory and take the prefix

```text
env -u PYTHONHOME -u PYTHONPATH -u UV_INTERNAL__PYTHONHOME \
    NUMBA_NUM_THREADS=4 OMP_NUM_THREADS=4 uv run --no-sync
```

The table below writes this prefix as `UV`. Paths no longer come from environment variables: the data locations are written in the `data` section of `configs/main.yaml`, relative to the repository root, and resolved by `Config.data_path` (`cache_dir` = `data/derived/codebench_cache_r4/`, `overlay_dir` = `data/derived/overlay_traces/`, `score_dir` = `data/derived/package_ranking_scores/`; see the README and `data/derived/README.md`).

## Rules

- Artefacts are not under version control (`.gitignore` excludes `outputs/`, `*.npz`, `*.npy`). Only `protocol_lock.draft.json` and, after the freeze, `protocol_lock.json` are under version control.
- The numbers in the paper's tables have exactly one source: the CSVs under `outputs/`. Every change to a number in `paper/` must point back to a row.
- When a conclusion changes, change it where it is written and do not start a second version; a file that has been overturned states at its top what overturned it.
