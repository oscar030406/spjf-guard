=== G4.3  AN ADDITIVE Omega(L) IS UNAVOIDABLE ===
construction: empty system, at t=0 the victim i (rank 0) and k jobs of
size L (ranks 1..k) arrive together.  All k servers are free.  Any policy
that fills all k servers with the higher-ranked jobs leaves i waiting until
the first completion.
   k     L   W_P[i]  W_FCFS[i]  excess
   1     5       5          0       5
   1    50      50          0      50
   2     5       5          0       5
   2    50      50          0      50
   3     5       5          0       5
   3    50      50          0      50
   4     5       5          0       5
   4    50      50          0      50
  excess = L for every k.  The policy learns no service time before the
  first completion, so an adversary may set all k sizes to L after the
  dispatch decision.  Hence any wrapper with B > 0 (which permits this
  full-width deviation, since over[i] = 0 < B) admits instances with
  excess >= L: the additive constant in Theorem A is at least L, for every k.

=== G4.5  COUNT / POSITION BUDGETS (Nudge-K, finite-skip) ===
(a) without a size bound a count budget gives NO guarantee: k overtakes of
    work X each cost excess X, and X is unbounded.
    k=1, one overtake per server of work X=     10 : excess of rank 0 =      10
    k=1, one overtake per server of work X=   1000 : excess of rank 0 =    1000
    k=1, one overtake per server of work X= 100000 : excess of rank 0 =  100000
    k=2, one overtake per server of work X=     10 : excess of rank 0 =      10
    k=2, one overtake per server of work X=   1000 : excess of rank 0 =    1000
    k=2, one overtake per server of work X= 100000 : excess of rank 0 =  100000
    k=4, one overtake per server of work X=     10 : excess of rank 0 =      10
    k=4, one overtake per server of work X=   1000 : excess of rank 0 =    1000
    k=4, one overtake per server of work X= 100000 : excess of rank 0 =  100000
(b) with sizes <= L, N overtakes cost at most N*L/k and that is attained.
    At the same guarantee G, a work budget B = kG admits B/xbar overtakes
    when the typical size is xbar, while the count budget admits only
    N = kG/L = B/L of them: the count budget is loose by the factor L/xbar.
     L   xbar   L/xbar   overtakes at G=100, k=2 : count budget / work budget
    100      1    100.0                                    2.0 / 200.0
    100     10     10.0                                    2.0 / 20.0
    100    100      1.0                                    2.0 / 2.0
     60      1     60.0                                    3.3 / 200.0
     60      5     12.0                                    3.3 / 40.0
(c) a count budget is also not NECESSARY: arbitrarily many tiny jobs may
    overtake at negligible excess, which a count budget forbids.
    k=1,    10 unit overtakers of a job of work 1000: excess =    10  (= m*1/k,  far below L = 1000; a count budget N < m forbids it outright)
    k=1,   100 unit overtakers of a job of work 1000: excess =   100  (= m*1/k,  far below L = 1000; a count budget N < m forbids it outright)
    k=1,  1000 unit overtakers of a job of work 1000: excess =  1000  (= m*1/k,  far below L = 1000; a count budget N < m forbids it outright)
